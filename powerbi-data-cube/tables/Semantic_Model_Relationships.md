# Semantic_Model_Relationships

## Table Overview
`Semantic_Model_Relationships` is a DMV (Dynamic Management View) metadata table that queries the semantic model's relationship structure using the `INFO.VIEW.RELATIONSHIPS()` function. This table provides a queryable catalog of all relationships in the Power BI data model, enabling dynamic documentation and model analysis.

Each row represents one relationship in the model, with details on cardinality, cross-filtering behavior, and participating tables/columns.

**Current Status**: Calculated table querying DMV metadata. Refreshes with model metadata changes.

---

## Specifications
- **Source**: DAX calculated table using `INFO.VIEW.RELATIONSHIPS()` DMV
- **Row Count**: Variable (one row per relationship in the model, typically 40-60)
- **Grain**: One row per model relationship
- **Primary Key**: ID (relationship identifier)
- **Incremental Refresh**: Not applicable (calculated table)
- **Partitioning Strategy**: Single partition
- **Source Columns**: 15 (DMV columns)
- **Calculated Columns**: 2 (Description, SeqNumber)

## Calculated Columns

### Description
```dax
Description = 
"The relationship links '" &
[FromTable] & "'[" & [FromColumn] & "] to '" &
[ToTable] & "'[" & [ToColumn] & "]. It is a " &
SWITCH(
    TRUE(),
    [FromCardinality] = "One" && [ToCardinality] = "One", "one-to-one relationship (1:1)",
    [FromCardinality] = "One" && [ToCardinality] = "Many", "one-to-many relationship (1:*)",
    [FromCardinality] = "Many" && [ToCardinality] = "One", "many-to-one relationship (Many:1)",
    [FromCardinality] = "Many" && [ToCardinality] = "Many", "many-to-many relationship (*:*)",
    "relationship"
) &
" and supports " &
SWITCH(
    [CrossFilteringBehavior],
    "BothDirections", "bidirectional cross-filtering, meaning that filters applied in either table will affect the other",
    "Single", "single-direction cross-filtering, meaning that filters flow only from the 'from' table to the 'to' table",
    [CrossFilteringBehavior]
) & "."
```

**Purpose**: Generates human-readable relationship description combining table/column names, cardinality, and cross-filter direction.

**Output Example**:
```
The relationship links 'Assignments'[WorkTemplate_Id] to 'Dim_WorkTemplates'[Id]. It is a many-to-one relationship (Many:1) and supports single-direction cross-filtering, meaning that filters flow only from the 'from' table to the 'to' table.
```

### SeqNumber
```dax
SeqNumber = 
RANKX(
    ALL(Semantic_Model_Relationships),
    Semantic_Model_Relationships[ID],
    ,
    ASC,
    DENSE
) + 200
```

**Purpose**: Assigns sequential number to relationships based on ID, offset by 200.

**Logic**:
- `RANKX` with `ASC, DENSE` creates sequential numbers starting at 1
- `+ 200` offset creates sequence starting at 201
- Offset likely avoids collision with other numbered elements in model

## DAX Query Patterns

### Example 1: All Relationships Summary
```dax
EVALUATE
SELECTCOLUMNS(
    Semantic_Model_Relationships,
    "Relationship_ID", Semantic_Model_Relationships[ID],
    "From", Semantic_Model_Relationships[FromTable] & "[" & Semantic_Model_Relationships[FromColumn] & "]",
    "To", Semantic_Model_Relationships[ToTable] & "[" & Semantic_Model_Relationships[ToColumn] & "]",
    "Cardinality", Semantic_Model_Relationships[FromCardinality] & ":" & Semantic_Model_Relationships[ToCardinality],
    "Direction", Semantic_Model_Relationships[CrossFilteringBehavior],
    "Active", Semantic_Model_Relationships[IsActive]
)
ORDER BY Semantic_Model_Relationships[ID]
```

### Example 2: Bidirectional Relationships
```dax
EVALUATE
FILTER(
    Semantic_Model_Relationships,
    Semantic_Model_Relationships[CrossFilteringBehavior] = "BothDirections"
)
ORDER BY Semantic_Model_Relationships[FromTable]
```

### Example 3: Inactive Relationships
```dax
EVALUATE
SELECTCOLUMNS(
    FILTER(
        Semantic_Model_Relationships,
        Semantic_Model_Relationships[IsActive] = FALSE()
    ),
    "Relationship", Semantic_Model_Relationships[Name],
    "From", Semantic_Model_Relationships[FromTable],
    "To", Semantic_Model_Relationships[ToTable],
    "Reason", "Inactive - requires USERELATIONSHIP()"
)
```

### Example 4: Relationships by Table
```dax
EVALUATE
FILTER(
    Semantic_Model_Relationships,
    Semantic_Model_Relationships[FromTable] = "Assignments"
        || Semantic_Model_Relationships[ToTable] = "Assignments"
)
ORDER BY Semantic_Model_Relationships[IsActive] DESC, Semantic_Model_Relationships[FromTable]
```

### Example 5: Many-to-Many Relationships
```dax
EVALUATE
FILTER(
    Semantic_Model_Relationships,
    Semantic_Model_Relationships[FromCardinality] = "Many"
        && Semantic_Model_Relationships[ToCardinality] = "Many"
)
```

### Example 6: Relationship Count by Direction
```dax
EVALUATE
SUMMARIZECOLUMNS(
    Semantic_Model_Relationships[CrossFilteringBehavior],
    "Relationship_Count", COUNTROWS(Semantic_Model_Relationships),
    "Active_Count", CALCULATE(COUNTROWS(Semantic_Model_Relationships), Semantic_Model_Relationships[IsActive] = TRUE()),
    "Inactive_Count", CALCULATE(COUNTROWS(Semantic_Model_Relationships), Semantic_Model_Relationships[IsActive] = FALSE())
)
```

## Data Model Pattern

### DMV Metadata Query Pattern
`Semantic_Model_Relationships` implements the DMV (Dynamic Management View) metadata query pattern, enabling programmatic access to model structure:

**Pattern Characteristics**:
- **DMV Function Source**: Uses `INFO.VIEW.RELATIONSHIPS()` to query model metadata
- **Calculated Table**: Refreshes with model, capturing current relationship structure
- **Self-Documenting**: Model documents its own relationship structure
- **Queryable Metadata**: Enables DAX queries against model relationships
- **Documentation Helper**: Used by measures to generate dynamic documentation

**DMV Information Schema**:
Power BI provides several `INFO.*` DMV functions:
- `INFO.TABLES()` - Table catalog
- `INFO.COLUMNS()` - Column catalog
- `INFO.MEASURES()` - Measure catalog
- `INFO.RELATIONSHIPS()` - Relationship catalog (this table)
- `INFO.PARTITIONS()` - Partition catalog
- `INFO.VIEW.*` - View variants with additional columns

The `.VIEW.` variant typically provides more detailed information than base `INFO.*` functions.

**Relationship Metadata Components**:

1. **Identity**: ID, Name, Relationship display
2. **Endpoints**: FromTable/Column, ToTable/Column
3. **Cardinality**: FromCardinality (One/Many), ToCardinality (One/Many)
4. **Behavior**: IsActive, CrossFilteringBehavior, RelyOnReferentialIntegrity
5. **Security**: SecurityFilteringBehavior
6. **State**: State (Ready, Error, etc.)

**Cardinality Patterns**:
- **Many-to-One (Many:1)**: Most common, fact to dimension
- **One-to-Many (1:Many)**: Same as Many:1 but reversed notation
- **One-to-One (1:1)**: Rare, typically role-playing dimensions
- **Many-to-Many (*:*)**: Bridge tables, complex relationships

**CrossFilteringBehavior Values**:
- **Single**: Unidirectional filtering (standard star schema)
- **BothDirections**: Bidirectional filtering (bridge tables, special cases)

**IsActive Flag**:
- **TRUE**: Active relationship, used by default in calculations
- **FALSE**: Inactive relationship, requires `USERELATIONSHIP()` to activate

**Inactive Relationship Use Cases**:
- Role-playing dimensions (e.g., multiple date relationships to Dim_Date_Reference)
- Alternative relationship paths
- Conditional relationship activation via measures

**Calculated Columns**:

1. **Description**: Human-readable relationship explanation
   - Combines table/column names
   - Translates cardinality to readable format (1:1, 1:*, Many:1, *:*)
   - Explains cross-filter direction impact
   - Used in documentation visuals and tooltips

2. **SeqNumber**: Sequential numbering with 200 offset
   - Enables consistent ordering
   - 200 offset suggests grouping with other numbered metadata
   - Used for sorting in reports

**Documentation Helper Integration**:
This table is used by documentation measures in `_Measures` table:
- **Doc - Related Relationships by Selected_Tables**: Filters this table to show relationships for selected tables
- Enables "What tables connect to this?" queries
- Powers model documentation reports

**Self-Documenting Pattern Benefits**:
1. **Always Current**: Automatically reflects model changes
2. **No Manual Maintenance**: Relationship catalog updates with model
3. **Query Capability**: DAX can analyze relationship structure
4. **Documentation Automation**: Generates reports about model structure
5. **Impact Analysis**: Identify tables affected by relationship changes
